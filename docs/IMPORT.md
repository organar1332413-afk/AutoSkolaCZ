# Импорт eTesty и обновление

ContentImporter.importPackage(bytes, mediaRoot) принимает промежуточный формат приложения, проверяет его и пишет нормализованные таблицы Room. Bootstrap использует встроенный sample при первом запуске. JSON — транспорт, а не база прогресса.

Официальный JSON/XML-экспорт или публичный API MD ČR не получен. Формат `sample-v1.json` не выдаётся за формат министерства. Автоматической выгрузки всего сайта здесь нет.

## Контракт v1

Manifest: formatVersion, databaseVersion, publicationDate, source, retrievedAt, sample, completeForB.
Question: officialId, category, textCs, points, licenceGroups, answers, media, translations, source.
Answer: code, textCs, correct.
Translation: locale, text, explanation, answers по коду, reviewStatus.
Media: относительный path, sha256, mimeType, опциональный answerCode.

CS-строки сохраняются без trim, перефразирования и нормализации. Токенизация использует позиции в оригинальной строке.

## Импорт

1. Ограничение размера, строгий JSON, известная версия формата, корректные даты и источник.
2. Уникальные ID, 2–3 ответа A/B/C, один правильный, согласованные ключи переводов.
3. Для production обязательны дата и баллы; v2 допускает вопросы без подтверждённой группы. Sample допускает неподтверждённые поля null/пустые.
4. Медиа: допустимые пути, canonical path, размер и SHA-256.
5. Подготовка медиа в отдельной папке; установка каталога по хешу пакета.
6. Room withTransaction: все записи, затем ActiveContent.
7. Повторный идентичный импорт не создаёт дубликатов и не откатывает активный указатель. Та же версия с другим содержимым отвергается. Mutex сериализует импорт в одном экземпляре.

При ошибке SQL активная база остаётся прежней. Неиспользованная папка после сбоя может потребовать будущей фоновой уборки; пользовательский прогресс не затрагивается. Домен source не доказывает подлинность пакета. Сейчас разрешён только встроенный sample, сетевой импорт не открыт.

## Подключение полного банка

Получить официальный фиксированный выпуск/экспорт и медиа. Написать адаптер именно к полученному формату, сверить точные CS-строки, IDs, ключи, баллы, категории B и медиа. При PDF вручную проверить неоднозначности извлечения и переносов. Не заполнять пробелы выдуманными вопросами. Переводы проверяются отдельно редактором и специалистом по ПДД. Перед распространением подтвердить права на официальные тексты и медиа.

## Будущее обновление — пока только дизайн

ContentUpdateSource — контракт для последующего загрузчика. Подписанный манифест содержит версию, дату, формат, размер, хеш и минимальную версию приложения. Подпись проверяется встроенным публичным ключом; SHA-256 не заменяет подпись. После проверки — временная загрузка, проверка полноты и атомарный импорт. История остаётся на старых редакциях, удалённые вопросы исчезают лишь из активной выдачи.

Сетевой загрузчик, подписи, downgrade-защита, WorkManager, очистка неиспользованных медиа и политика обновления во время экзамена — последующие этапы. Текущий importer нельзя считать готовым публичным сетевым API. Обновление переводов пока требует новой неизменяемой версии пакета.

## Stage 3A — внутренний контракт v2

Это **формат Autoškola CZ**, не ответ API Министерства. V1 sample продолжает читаться через `ContentPackageCodec`. V2 манифест: `formatVersion=2`, `databaseVersion`, `publicationDate`, `source`, `retrievedAt`, `sample`, `groupReadiness`. Каждая запись готовности содержит группу, версию правил, три флага полноты и источник. Вопрос v2 содержит `eligibility: [{licenceGroup, source}]` вместо v1 `licenceGroups`; записи только положительные. Вопрос production с пустым `eligibility` допустим к импорту, но UNKNOWN для всех групп и не участвует в экзамене.

Валидатор отвергает T и другие неподдерживаемые группы, дубликаты связей, неполные ответы и квоты, некорректные баллы, небезопасные пути, sample с заявленной готовностью и ложную готовность по фактическому пулу. Импорт сверяет локальные медиа с SHA-256. Формат допускает video MIME как метаданные; группа с обязательным видео пока не готова к реальному экзамену. Приложение не обращается к внутреннему web endpoint eTesty во время работы.

Следующий этап: получить доверенный фиксированный источник, извлечь точные тексты и медиа отдельным importer, подтвердить `QuestionRevision ↔ LicenceGroup` для каждой группы и полноту mapping, собрать versioned package v2, прогнать проверку и только затем отметить readiness. Не выводить группу из темы или текста вопроса.

## Reviewed-source intake (первый шаг следующего этапа)

`python -m tools.official_import.build_package INPUT_DIR EMPTY_OUTPUT_DIR` создаёт детерминированные `package-v2.json`, `audit.json` и копии локального медиа. Это **компилятор проверенных промежуточных файлов**, а не парсер неизвестного формата экспорта Министерства и не scraper. Выходной JSON принадлежит приложению. В репозитории нет выгруженного официального банка, синтетические тестовые вопросы не поставляются приложению.

Входная директория содержит:

| Файл | Содержание |
| --- | --- |
| `source.json` | `databaseVersion`, `publicationDate` (ISO date), `retrievedAt` (ISO timestamp with zone), официальный `source` URL, имя фиксированного `exportFile`, его `exportSha256` |
| `exportFile` | неизменённый файл полученного источника; имя без каталогов |
| `questions.json` | массив `{officialId, category, textCs, points, answers, media, source}`; ответы `{code, textCs, correct}`, медиа `{path, mimeType, answerCode?}` |
| `eligibility.json` | только положительные записи `{officialId, licenceGroup, source, evidenceRef}`; `evidenceRef` указывает место явного подтверждения в источнике или приложенном проверенном документе |
| `coverage.json` | записи `{licenceGroup, blueprintVersion, eligibilityComplete, mappingSha256, exportSha256, officialIds, source, evidenceRef}`; `officialIds` — отсортированный полный перечень всех положительно сопоставленных ID группы |
| `media/...` | оригинальные локальные файлы медиа, на которые ссылаются вопросы |

Поддерживаются только A/B/BE/C/CE/D/DE, категории и баллы текущего `ExamConfiguration` (`etesty-2026-09-v1`). Чешские строки переносятся как есть; неизвестные связи не превращаются в универсальные. У `coverage.json` может быть запись с `eligibilityComplete=false`, либо её может вообще не быть: группа остаётся закрытой. Положительная аттестация требует **проверки человеком**, что источник содержит исчерпывающий перечень группы. Совпадение SHA-256, ID и экзаменационных квот проверяет внутреннюю целостность, но само по себе не доказывает официальность файла или полноту опубликованного банка. Не выставлять `eligibilityComplete=true` только потому, что удалось собрать 25 вопросов.

Компилятор сверяет хеш фиксированного экспорта, каждую связь и inventory, уникальность ID, структуру ответов, локальные медиа и фактические квоты. `contentComplete` означает, что в **подтверждённом пуле** хватает вопросов с нужными баллами; `mediaComplete` требует поддерживаемых приложением изображений. Неподдерживаемое обязательное видео сохраняется с исходным MIME и хешем, но закрывает экзамен группы. Результат всё равно ещё должен пройти `ContentPackageCodec`, `PackageValidator` и импорт в Room; напрямую Android не скачивает источник. `audit.json` оставляет хеши файлов и указатели на доказательства для ручной сверки. Не редактировать готовый пакет после проверки; повторный запуск по тем же входным файлам даёт те же байты.

Пример запуска после получения и ручной проверки реального источника:

```sh
python -m tools.official_import.build_package reviewed-export prepared-package
python -m unittest discover -s tools -p 'test_*.py' -v
```

В июне 2026 Министерство сообщило, что публичного API разработчиков нет, а индивидуальный экспорт базы возможен по запросу за плату: [ответ MD ČR](https://md.gov.cz/Ministerstvo/Zadost-o-poskytnuti-informace-(1)/Poskytnute-informace/Testove-otazky-(1)). Конкретный формат, состав медиа и способ доказательства полного mapping нужно уточнить по полученному экспорту. Если он не содержит явного разделения по группам, запросить эту информацию отдельно; не выводить её из темы, текста или случайных тестов.
